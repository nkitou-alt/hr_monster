# 研修プログラム開発（マナブー）

研修のアイデアを、当日そのまま実施できるプログラムに変えるスキル。
研修づくりの1次設計（最小コンテンツ化と時間の検証）と2次設計（実施用の作り込み）を担当する。

## 最初に読むもの

1. `references/training-context.md`：良い研修の前提（特に第3〜5章、第8〜9章）
2. `references/design-process.md`：設計の進め方（このスキルは「フェーズ1・2」と「ワークシートの設問設計」を担当）
3. 入力：研修コンセプトシート（「研修コンセプト設計」スキルの出力）。無ければ、対象者・時間・学習目標・メインワークを最初に確認する。

## 進め方

### 1. 時間で殴り返す（1次設計）

- 最も負荷が高く、崩れると研修が成立しないブロック（多くはメインワーク）から分解する。
- 1人あたり・1ラウンドあたりの分数まで分解し、「単位時間 × 人数」で積む。
- 分単位の時間割をつくり、合計が器（実働時間）に収まることを**計算で示す**。
- 時間ルールを当てる：同種のワークを連続させない／90分ごとに10分休憩／午後は対話で立ち上げる／レクチャーは長くて15分／長い個人ワークの間に「動」を挟む／各セッション末に3分のリフレクション。
- 押したときの**削り順**と、余ったときの延ばし先を決める。メインワークは最後まで削らない。
- 人数の端数（奇数グループなど）の吸収ルールを決める。

### 2. 教材をつくる（2次設計）

- **物理フォーマットを最初に確定する**：スライドのテンプレート、配布物の判型、色とフォント。サンプルがあれば「準拠必須か、参考か」を確認する。
- **大物は二段階**：スライド50枚超や長い台本は、構成表を出して承認を得てから本制作する。
- 各セッションは「扉 → 狙い → 進行 → 内容 → まとめ → リフレクション」の型で組む。基本サイクルは「概説 → 例 → 演習 → 振り返り」。
- 事前学習（テキスト・動画）は、情報開示マップに従う。当日の山場の種を明かさない。
- 研修中にAIを使うワークでは、出力を答えではなく吟味の叩き台として扱い、吟味の時間を時間割に入れる。
- 学びを職場で誰に、どの場で話すかまで設計する（持ち帰り物、声に出す練習）。

### 3. ワークシートの設問を磨く

- その時点で導入済みの言葉だけを使う。未習の概念語を先取りしない。
- まだ体験していない効果を予測させない。行動の選択肢を開く問いにする。
- ロール別シート（話し手・聴き手・観察者など）は、役割ごとに視点を厳密に分ける。
- 設問番号は記入順に、記入欄は求める分量に見合う高さにする。
- 中核の問い・定義は正文からコピーし、改変しない。

### 4. 自己点検して提出

品質基準とNGパターン（training-context.md 第8〜9章）で点検し、さらに良くする観点を2〜3個添えて採否を仰ぐ。

## 出力（必要なものを、この順で）

1. **時間割**：開始・終了時刻、セッション、学習要素、分数、ねらい。合計の検算つき
2. **削り順と延ばし先**
3. **事前学習の構成**：テキストの章立て、動画の本数と長さ、宿題（正文）
4. **スライド構成表**：セッションごとのスライドタイトルと要点
5. **ワークシート**：設問と記入欄の大きさの指定
6. **講師ガイド**：各ワークの指示文（台本）、想定される反応、つまずいたときの足場かけ

## 品質チェック

- [ ] 時間割の合計が器に収まっている（検算を示した）
- [ ] レクチャーが15分を超えて続く箇所がない
- [ ] すべてのセッション末にリフレクション枠がある
- [ ] 対話ワークに「良い問い・安全な場・足場かけ・対話のゴール」がそろっている
- [ ] 学習目標と各コンテンツが対応している
