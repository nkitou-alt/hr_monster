# 研修評価（ミキワン）

「楽しかった」で終わらせず、研修が本当に学びと行動の変化につながったかを確かめるスキル。
評価は研修が終わってから考えるものではない。設計の段階で、測る仕組みを組み込む。

## 最初に読むもの

1. `references/training-context.md`：特に第6章（実践知ループ）、第8章（測定整合の原則）
2. `references/design-process.md`：特に「実施後：フィードバックの還元」
3. 入力：学習目標とセオリー・オブ・チェンジ（「研修コンセプト設計」の出力）、時間割とリフレクション設問（「研修プログラム開発」の出力）。実施後の分析では、アンケートの回答データ。

## 進め方

### 1. 測定整合表をつくる（設計段階）

学習目標ごとに、次の4つが**同じ語彙で貫通**しているかを1枚の表にする。

| 学習目標 | セッション末のリフレクション設問 | 直後アンケートの到達度設問 | 事後フォローの設問 |

受講者が日中に書いた言葉を、アンケートに答えるときに思い出せる構造にする。測る言葉が学ぶ言葉とズレていると、学んだのに測れない。ズレを見つけたら、学習目標の語彙に合わせて直す。

### 2. アンケートと事後フォローを設計する

- **直後アンケート**：学習目標ごとの到達度（自己評価）／いちばん印象に残った場面と理由（自由記述）／職場で最初にやること（具体的な行動）／運営面の改善点。
- **事後フォロー**（1か月後が目安）：行動が起きたか、何回か、何が起きたか、うまくいかなかったことは何か。セオリー・オブ・チェンジの「行動」と「成果」の段に対応させる。
- 匿名か記名かを決める。率直さを取るなら匿名、事後フォローと結びつけるなら記名。どちらにするかは問い返す。
- 満足度だけを聞かない。満足度は高くても行動が変わらない研修はある。

### 3. 結果を分析する（実施後）

- 数値は平均だけでなく、分布と低い回答の理由を見る。
- 自由記述は、AIで構造化して傾向をつかむ。ただし出力は結論ではなく吟味の対象として扱い、元の回答に戻って確かめる。
- セオリー・オブ・チェンジのどの段で止まっているか（内的変化は起きたが行動に移っていない、など）を特定する。
- 受講者の実践の工夫は「実践知」として収穫し、次回の教材や個別 context.md に還流する（実践知ループ）。

### 4. 改善を提案する

- 改善案は、効果の大きさと手間で並べ、上位3つに絞る。
- その研修に固有の学びは個別 context.md へ、複数の研修に効く一般則は共通コンテキストへ。共通に上げる基準は「3つ目の研修でもそのまま使えるか」。

## 出力（段階に応じて）

設計段階：
1. **測定整合表**
2. **直後アンケート**（設問・選択肢・回答形式）
3. **事後フォローの設問**と実施タイミング

実施後：
4. **評価レポート**：結論（3行）／学習目標ごとの到達度／セオリー・オブ・チェンジのどこで止まったか／印象に残った場面の傾向／収穫した実践知／改善提案（上位3つ）

## 品質チェック

- [ ] 学習目標・リフレクション・アンケート・事後フォローが同じ語彙でつながっている
- [ ] 満足度以外に、行動の変化を測る設問がある
- [ ] 自由記述の分析結果を、元の回答に戻って確かめた
- [ ] 改善提案が、効果と手間で優先順位づけされている
