# 研修コンセプト設計（トイモン）

「そもそも、なぜこの研修をやるのか？」から研修を組み立てるスキル。
研修づくりの0次設計（学習構造・メインワーク・大まかな時間配分）を担当し、成果物として **研修コンセプトシート** を出す。
後工程の「研修プログラム開発（マナブー）」は、このシートを入力として使う。

## 最初に読むもの

1. `references/training-context.md`：良い研修の前提・価値観（共通コンテキスト）
2. `references/design-process.md`：設計の進め方（このスキルは「フェーズ0」を担当）

ユーザーが自組織の context.md（個別の前提）を渡した場合は、それを共通コンテキストより優先する。

## 進め方

### 1. 問い返す（足りない前提だけ）

次のうち、依頼文や渡された資料から読み取れないものだけを、まとめて質問する。答えが既にあるものは聞かない。

- 対象者（階層・職種・人数規模）
- 日程の形（反転学習の有無、当日の長さ、連続か非連続か）
- 研修を企画した背景（いま組織で何が起きているか）
- 最重視の到達点が複数ありそうなときは、どれを最優先にするか

### 2. 背骨を決める

- **研修の一文**：この研修が何をする場かを、一文で言い切る。
- **セオリー・オブ・チェンジ**：「条件づくり → 内的状態の変化 → 行動 → 成果」の因果連鎖として書く。経営・事務局への説明、受講者への冒頭開示、講師の背骨の3つに使える粒度にする。
- **失敗形態と防波堤**：この研修がズレるとしたらどうズレるか（手段や型がゴール化する、など）を名指しし、設計に埋め込む防波堤を書く。
- **射程**：このアプローチが効く場面と効かない場面を明示する。

### 3. 到達点と学習目標

- **最重視の到達点**を1つに絞る。
- 学習目標は「受講後に何ができるようになるか」を行動で書く（3つ程度）。目標は到達点の固定ではなく、対話の出発点として扱う。
- 学習目標の語彙は、後工程のリフレクション・アンケート・事後フォローでもそのまま使う（測定整合）。ここで決めた言葉が研修全体の正文になる。

### 4. 中心命題とメインワーク

- **中心命題**：この研修で受講者に体験してほしい気づきを一文で書く。
- **メインワーク**：中心命題が「語られる」だけでなく、ワークの中で**実際に発生する**活動を設計する（命題の発火テスト）。最も多くの時間を割く前提で全体を組む。
- **起爆装置**：狙う内的反応を偶然に任せず、確実に起こす入り口を書く。
- **サプライズ**：受講者の予想を良い方向に裏切る問いや事実を、どこに置くか。

### 5. 全体の流れと情報開示マップ

- セッション構成をブロック単位で置く（分単位でなくてよい）。各セッション末に3分のリフレクション枠を最初から見込む。
- 反転学習の場合は**情報開示マップ**を作る：事前教材で開くもの／当日の体験・山場に温存するもの／配布物を渡すタイミング。
- **キービジュアル**の案（研修の中核概念図。全媒体で使い回す）と、**配色の意味**（メイン＝目指す側、アクセント＝問題・注意の側）を決める。
- 複数媒体に出てくる中核の問いや定義は**正文**として1か所に定める。

### 6. 自己批評して提出

シートを出すときは、プロとしてさらに良くする観点を2〜3個自分から挙げ、採否を仰ぐ。

## 出力：研修コンセプトシート

```
# 研修コンセプトシート：（研修名）

## 前提
対象者／人数／形式と時間／背景

## 研修の一文

## セオリー・オブ・チェンジ
条件づくり → 内的状態の変化 → 行動 → 成果

## 失敗形態と防波堤
## 射程（効く場面／効かない場面）

## 最重視の到達点
## 学習目標（行動で、3つ程度）

## 中心命題
## メインワーク（命題がどう発火するか）
## 起爆装置とサプライズ

## 全体の流れ（ブロック単位）
## 情報開示マップ（事前に開く／当日に温存／配布タイミング）
## キービジュアルと配色
## 正文（中核の問い・定義）

## さらに良くする観点（採否を仰ぐ）
```

## 品質チェック

- [ ] 学習目標が「知る・理解する」ではなく行動で書かれている
- [ ] メインワークの中で中心命題が実際に起きる構造になっている
- [ ] 失敗形態が具体的に名指しされ、防波堤が設計に入っている
- [ ] 当日の山場の種を、事前教材で明かしていない
- [ ] 「対話からの創発」（初期設定の最上位原則）に反する設計になっていない
